# Santa Ops 2026 每日经营驾驶舱

经营、广告、库存、推广、关键词、竞品与每日操作使用统一数据接口。阿里云上线及跨电脑迁移请遵循 [数据迁移与回滚说明](docs/deployment/aliyun-data-migration.md)。数据库备份使用 `pnpm ops:backup`，校验使用 `pnpm ops:verify-backup`。

这是一个完全本地运行的圣诞服经营驾驶舱。业务报告、广告报告和手工记录只保存在当前浏览器的 IndexedDB（数据库名 `santa-ops`）中，不上传到服务器。

## 首次启动

在项目目录运行 `pnpm install`，然后运行 `pnpm dev`，打开终端显示的 Local URL。首次启动不会展示演示经营值；KPI 使用破折号，并提示先导入报告。

## 每日操作

1. 点击“导入今日数据”，选择业务报告或广告报告（CSV/XLSX/XLS）。系统优先按报告列名识别类型；只有列名不足以识别时，才用文件名中的 `ad`、`ads` 或 `advertising` 作为辅助提示。
2. 查看有效行、问题行和重复记录预览。发现重复键时必须明确选择“忽略重复”或“替换旧记录”，再保存。
3. 在“手工记录”中填写日期、尺码、入库、库存调整、事件、问题、动作和完成状态。促销、Deal、调价等事件会出现在销售趋势图参考线上。没有观测到入库或库存调整时请留空；留空会保持为未知，不会自动变成零。
4. 使用日期、尺码（全部/L/XL/2XL/3XL）和每日/每周/累计筛选。每周按 ISO 周一开始；累计均价、ACOS 和毛利率按累计分子/分母重算。

刷新或重新打开页面会从 IndexedDB 重新载入数据。若要清空数据，请在浏览器开发者工具的 Application/Storage 中删除 `santa-ops` IndexedDB；此操作不可恢复。

每次正式导入会在同一个本地事务中保存：原始文件字节（`rawImports`）、逐行原始值（`rawRows`）、标准化结果审计副本（`derivedResults`）、正式业务/广告记录和带引用键的导入日志（`imports`）。因此可以从导入日志追溯到原始证据和当时生成的标准化结果。

## 示例文件与对账

- [`public/sample-business-report.csv`](public/sample-business-report.csv)：94 件，销售额 US$5,516，覆盖 L/XL/2XL/3XL 的主 SKU/ASIN。
- [`public/sample-ad-report.csv`](public/sample-ad-report.csv)：广告花费 US$800，广告销售额 US$4,000，ACOS 20%，覆盖四个尺码主 ASIN。

两份示例导入后会由真实计算产生红/黄/绿状态，不包含写死的仪表盘结果。示例业务报告没有库存字段，因此库存与相关预测会明确显示“数据不完整”，不会显示为零库存或零利润。

运行 `pnpm vitest run --exclude tests/rendered-html.test.mjs`、`pnpm typecheck`、`pnpm lint`、`pnpm plan:check` 和 `pnpm test`。`pnpm test` 已包含生产构建和独立 HTML 渲染测试；项目不包含部署步骤。

## GitHub 与服务器部署说明

本仓库可以托管在 GitHub，用于保存源码、版本记录和后续服务器部署。当前项目是 Vinext/React 应用，生产运行方式是先构建再启动 Node 服务：

```bash
pnpm install
pnpm build
PORT=3010 pnpm start
```

本项目不建议直接使用 GitHub Pages 作为最终运营环境：GitHub Pages 只适合纯静态页面，而当前应用包含 Vinext 服务端运行产物。若只是保存代码，请直接推送到 GitHub；若要在其它电脑通过网址访问，请部署到阿里云 ECS、Vercel、Netlify 或其它可运行 Node 服务的平台。

重要：当前经营数据保存在访问者浏览器本地 IndexedDB（数据库名 `santa-ops`）中。即使网站部署到服务器，不同电脑默认也不会自动共享同一份导入数据。若需要多电脑同步库存、广告、推广计划和每日操作，需要后续接入云端数据库。

## 第二版：计划与库存

驾驶舱右上角的“计划与库存”会打开独立的经营管理页；原有仪表盘、KPI 顺序和四张折线图保持不变。首次进入时，系统会把第一版保存的周计划权重转换为 ISO 周一开始的日计划：原始周计划的周总量不会改变，尺码按采购数量权重以确定性的最大余数法分配。此初始化计划保存到本机 IndexedDB，之后以保存后的日计划作为驾驶舱计划销量和完成率的来源。

在“日度计划”中可直接调整日期和 L、XL、2XL、3XL 销量。计划总量 2900–3100 件（含边界）显示绿色并允许保存；2899 或 3101 等范围外计划显示红色且无法保存。保存时必须填写调整原因，系统保留当前有效计划及最近一次调整信息。

“导入库存报告”支持 CSV、XLSX、XLS，可识别 Amazon 的 SKU/ASIN 与 FBA 可售库存；未映射标识只会进入问题清单。每个尺码可维护在途数量和预计到仓日期；留空即表示未知，不会当作 0。

风险区要求近 7 个连续自然日销量，以及完整的可售、预留、不可售、在途和剩余计划数据。季末积压率超过 15% 且不超过 25% 为黄色，超过 25% 或预计到仓晚于预计售罄日为红色；缺失数据明确显示“数据不足”。四个尺码独立展示，任一红色风险会保留在汇总中。
