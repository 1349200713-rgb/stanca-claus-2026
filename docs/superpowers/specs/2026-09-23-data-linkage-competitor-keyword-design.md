# Santa Ops 数据联动、竞品与关键词跟踪设计说明

## 1. 目标

将现有经营驾驶舱、计划与库存、广告推广、推广复盘和每日操作从“页面各自计算”升级为同一套可追溯的经营数据链路，并补齐竞品每日跟踪、核心关键词排名、流量与广告漏斗。

最终需要回答四类经营问题：

1. 销量或利润为什么变化。
2. 关键词排名、竞品动作、流量、广告和转化之间如何关联。
3. 操盘手当天采取了什么动作，3天和7天后是否有效。
4. 当前页面展示的是有效零值、缺失数据还是过期数据。

本阶段采用“Excel批量导入为主、页面手工维护、预留第三方API接口”的方式。正式数据保存在阿里云服务器，浏览器IndexedDB仅用于迁移旧数据和短期缓存，不再作为跨电脑共享数据的权威来源。

## 2. 范围

本阶段包括：

- 统一云端数据存储与读取接口。
- 统一商品、日期和运营对象的关联规则。
- 新增竞品跟踪页面。
- 新增关键词排名页面。
- 推广复盘增加曝光、点击、访问、CTR、CPC、CVR、TACOS等指标。
- 经营首页增加关键词异常和竞品动态摘要。
- 异常一键生成每日操作，并对比动作前后3天、7天效果。
- Excel/CSV导入、手动新增、修改、删除和导入审计。
- 将浏览器中已有数据安全迁移到云端，迁移前不清除本地数据。

本阶段不包括：

- 自动抓取亚马逊搜索结果页面。
- 自动估算无法从现有报表获得的竞品真实销量。
- 直接修改亚马逊广告、价格、Listing或库存。
- 第三方工具付费API的正式接入；只保留稳定的适配接口。
- 多租户、复杂审批流或细粒度角色权限。

## 3. 权威数据与关联主键

### 3.1 标准维度

所有业务数据尽量关联到以下标准维度：

- `marketplace`：站点，当前默认`US`。
- `date`：经营日期，ISO格式`YYYY-MM-DD`。
- `asin`：我方ASIN。
- `sku`：我方SKU。
- `size`：L、XL、2XL、3XL。
- `keywordId`：标准关键词标识。
- `competitorAsin`：竞品ASIN。

商品主数据维护ASIN、SKU、尺码、品名和站点映射。导入记录缺少ASIN但存在已映射SKU时，由商品主数据补齐ASIN；无法映射的记录进入问题清单，不进入正式汇总。

### 3.2 唯一键

- 经营数据：`marketplace + date + asin + sku`。
- 广告汇总：`marketplace + date + asin + campaign`；缺少ASIN时保留为未映射记录，不错误归入全部ASIN。
- 库存快照：`marketplace + date + asin + sku`。
- 推广计划：`marketplace + date + asin`；允许另设“全店计划”行，但必须明确标记作用域。
- 竞品快照：`marketplace + date + competitorAsin`。
- 关键词排名：`marketplace + date + asin + keywordId`。
- 竞品关键词排名：`marketplace + date + competitorAsin + keywordId`。
- 每日操作：独立ID，并可选关联`asin`、`sku`、`keywordId`、`competitorAsin`和异常ID。

同一唯一键重复导入时，用户选择忽略或更新。更新产生新版本和审计记录，不直接抹除历史证据。

## 4. 云端数据架构

### 4.1 服务器

阿里云现有Node服务增加受保护的数据API和持久化数据库。前端通过同源HTTPS接口读取和保存数据，避免浏览器跨域和明文凭据。

数据库采用关系型结构。第一阶段可使用服务器本机SQLite并每日备份；数据量或多人并发明显增加时可迁移至阿里云RDS MySQL。业务层通过仓储接口隔离具体数据库，迁移数据库不改变页面接口。

### 4.2 API边界

API按资源划分：商品主数据、经营记录、广告记录、库存、推广计划、竞品快照、关键词排名、每日操作、异常、导入批次和数据健康状态。第三方API以后只写入同一标准模型，不直接改变页面计算逻辑。

写操作必须校验字段、范围、日期和唯一键。批量导入采用事务：正式数据和导入日志同时成功或同时失败。

### 4.3 本地数据迁移

首次升级后显示“迁移本机数据”入口。迁移流程先读取IndexedDB，预览各类型数量和冲突，再写入云端。迁移成功后保留本地数据作为只读备份，直至用户明确确认清理。本阶段不自动删除任何本地记录。

## 5. 数据模型

### 5.1 竞品每日快照

字段包括：记录日期、站点、竞品ASIN、品牌、品名、价格、优惠类型、优惠金额或比例、Deal状态、评分、评论数、BSR类目、BSR排名、预计销量、库存状态、来源、备注、更新时间。

预计销量是可选值，必须同时记录来源；手工判断和第三方工具估算不得展示为亚马逊真实销量。价格、评分、评论数和BSR允许为空，空值保持未知，不转换为零。

### 5.2 关键词主数据与每日排名

关键词主数据字段包括：标准关键词、关键词分组、优先级、目标ASIN、启用状态和备注。

每日排名字段包括：日期、站点、关键词、我方ASIN、自然排名、广告排名、搜索页码、是否收录、采集来源、备注和更新时间。竞品排名使用相同日期和关键词，关联竞品ASIN。

排名数值越小越好。未收录或超出监测范围使用明确状态，不保存为0。自然排名和广告排名分别存储，不互相替代。

### 5.3 流量与广告漏斗

业务和广告数据补充或标准化：曝光量、点击量、访问量/Sessions、页面浏览量、广告订单、总订单、广告销售额、总销售额、广告花费和自然订单。

派生指标统一计算：

- CTR = 点击量 / 曝光量。
- CPC = 广告花费 / 点击量。
- CVR = 总订单 / 访问量；广告CVR单独使用广告订单 / 广告点击量。
- ACOS = 广告花费 / 广告销售额。
- TACOS = 广告花费 / 总销售额。
- 自然订单 = 总订单 - 广告订单；结果小于0时标记数据冲突，不截断为看似正常的0。

分母为0且分子也为0时显示0%；分母缺失或分子存在但分母为0时显示“无法计算”并产生数据质量提示。

### 5.4 运营事件和每日操作

操作记录补充：分类、优先级、负责人、截止日期、关联ASIN/SKU/关键词/竞品、异常来源、调整前快照、调整后3天快照、调整后7天快照和复盘结论。

操作分类包括调价、优惠券、广告预算、竞价、否词、关键词、Listing、站外推广、测评、库存和其他。操作完成不等于有效；效果状态单独使用“待观察、有效、无明显变化、负向、数据不足”。

## 6. 页面设计

### 6.1 统一导航和筛选

顶部导航顺序：经营驾驶舱、计划与库存、广告推广、推广复盘、关键词排名、竞品跟踪、每日操作。

所有页面共享日期范围、站点、ASIN、SKU和尺码筛选；关键词相关页面增加关键词筛选，竞品页面增加竞品ASIN筛选。从首页异常进入子页面时自动带入筛选条件，返回时保留原条件。

### 6.2 竞品跟踪页面

顶部指标：跟踪竞品数、今日降价竞品、新增优惠竞品、BSR提升竞品、评论增长最快竞品和异常数。

页面包括竞品每日明细、价格与优惠走势、BSR走势、评分与评论变化、我方与竞品对比。支持Excel/CSV导入、单条新增、修改和删除；删除需二次确认并写入审计日志。

### 6.3 关键词排名页面

顶部指标：核心关键词数、首页关键词数、前10名关键词数、排名上升数、排名下降数、广告占位数和连续下降数。

页面包括每日排名表、自然与广告排名双折线、关键词排名热力图、我方与竞品位置对比。折线纵轴反向显示，使排名改善在视觉上向上。未收录使用中性缺失状态，不与真实排名连接成误导折线。

### 6.4 推广复盘页面

保留现有计划与实际图表布局，新增：

- 曝光量与点击量。
- 访问量与订单量。
- CTR、CPC和CVR。
- ACOS与TACOS。
- 广告订单与自然订单。
- 关键词排名与销量。
- 关键词排名与广告花费。

支持7日、14日、30日和自定义日期。图表可按ASIN、SKU、尺码和关键词筛选，并标记调价、加预算、优惠券、否词、Listing修改和站外推广事件。

### 6.5 经营驾驶舱

首页增加两个紧凑摘要：

- 关键词异常：排名下降、流量下降、广告位丢失、未收录。
- 竞品动态：降价、新增优惠、BSR突升、评论快速增加。

首页只展示优先级最高的记录，并提供“查看全部”。点击记录进入对应页面并保留上下文。

### 6.6 每日操作

异常可一键生成操作记录，自动带入日期、对象、原因、建议动作和风险级别。完成动作后，系统在数据充分时自动生成调整前后3天、7天对比；不足观察窗口时显示剩余等待天数。

## 7. Excel/CSV导入与手工维护

竞品模板至少需要日期和竞品ASIN；关键词模板至少需要日期、关键词、我方ASIN，以及自然排名、广告排名或未收录状态之一。流量数据至少需要日期、ASIN和访问量。

导入流程：选择文件、识别类型、预览字段映射、显示有效/问题/重复行、选择重复策略、保存结果。结果明确显示新增、更新、忽略和失败数量。保存导入批次、文件名、上传时间、原始行、标准化结果和错误信息。

手工维护使用与导入相同的校验和唯一键，避免页面输入产生导入无法识别的数据。

## 8. 异常规则

### 8.1 关键词

- 自然排名单日下降5至9位：黄色。
- 自然排名单日下降10位及以上：红色。
- 连续3个有数据的自然日下降：生成持续下滑异常。
- 有曝光无点击：提示检查主图、价格、标题和相关性。
- 有点击无订单：提示检查Listing、评价、优惠和流量精准度。
- 广告排名存在且自然排名连续下降：提示广告依赖。

### 8.2 竞品

- 竞品降价5%及以上：价格异常。
- 新增Coupon或Deal：促销异常。
- BSR排名单日改善20%及以上：竞争升温提示。
- 评论增长超过可配置阈值：评论增长提示。
- 我方价格高于主要竞品且CVR下降：红色竞争风险。
- 竞品排名上涨同时我方关键词排名下降：竞争关联风险。

### 8.3 广告与流量

- CPC高于目标20%及以上：竞价成本异常。
- CTR或CVR低于对应目标20%及以上：黄色；连续3个有数据日未改善升级为红色。
- ACOS高于目标且连续3个有数据日未改善：红色。
- 访问量下降而曝光稳定：点击获取异常。
- 访问量稳定而订单下降：转化异常。
- 广告订单上涨而自然订单未增长：广告依赖提示。

阈值集中保存在配置中，页面可查看当前阈值；第一阶段不提供复杂的按用户自定义规则编辑器。

## 9. 数据健康与零值规则

每个页面显示各数据源最后成功导入时间、覆盖日期、有效记录数、缺失日期、未映射对象和失败行数。

显示规则：

- `0`只表示源数据明确记录为零。
- `—`表示无记录或不可计算。
- “未上传”表示该日期应有数据但尚无成功导入批次。
- “数据过期”表示最后更新时间超过对应数据源的时效阈值。

异常统计只计算已有必要数据且已到达的经营日期，不把未来日期或缺失数据计为经营异常。数据缺失由数据健康模块单独提醒。

## 10. 安全、备份和审计

- 写接口需要现有网站访问认证，不在浏览器保存数据库密码。
- 上传文件限制扩展名、大小和工作表行数；服务端再次校验。
- 数据库每日自动备份，至少保留最近30个每日备份。
- 导入、编辑和删除都记录时间、对象、修改前后值和操作来源。
- 日志不得记录登录密码、密钥或完整会话令牌。

## 11. 验收标准

- 同一账号在两台电脑打开网站，看到一致的正式数据。
- 旧IndexedDB数据能够预览冲突后迁移，迁移失败不会删除本地数据。
- 经营、广告、库存、推广、关键词、竞品和操作记录能按日期与商品维度关联。
- 竞品和关键词文件可以预览、导入、重复更新并保留审计证据。
- 手工新增、修改和删除在刷新及另一台电脑打开后仍然存在。
- 推广复盘正确展示曝光、点击、访问、CTR、CPC、CVR、ACOS和TACOS。
- 缺失值不显示为0，未收录排名不显示为第0名。
- 排名折线方向符合“数值越小越好”，缺失区间不绘制误导连线。
- 点击首页关键词或竞品异常能打开目标页面并保留筛选条件。
- 异常可以生成每日操作，并在数据充足时显示动作前后3天、7天效果。
- 同一唯一键并发或重复写入不会产生重复正式记录。
- 现有经营驾驶舱、计划库存、广告推广、推广复盘、每日操作和折线图继续通过回归测试。

## 12. 实施顺序

1. 建立统一商品维度、云端数据库、API、备份和本地数据迁移。
2. 将现有经营、广告、库存、推广计划和每日操作切换为云端数据源。
3. 增加竞品与关键词数据模型、导入器和维护页面。
4. 补齐流量指标、复盘图表和全局筛选联动。
5. 增加异常规则、首页摘要和操作效果闭环。

每一步必须保持现有页面可用，并通过已有回归测试后再进入下一步。
